## 任务

新建 `docs/pi/rpi-gpio-robust.md`——**GPIO 操作的健壮写法**。它只回答一个问题：**接线正确、代码能跑之后，GPIO 会在什么情况下给出「看起来对、实际错」的结果，以及怎么防。** 定位是 `rpi-gpio-pinout.md` 的下游专章，不是它的副本。

必写的七块（顺序你定，每块都要给「症状 → 成因 → 防线」三段）：

1. **异常退出后引脚保持什么状态**——进程崩溃/被 kill/未 `finally` 释放时，输出停在最后一次电平；继电器、电机这类负载的后果与兜底做法（硬件默认关断，不靠固件）。
2. **上电与重启瞬间的电平**——GPIO 在被程序接管前是输入/上拉还是别的状态、`claim` 输出那一刻会不会先翻转一次（`rpi-gpio-pinout.md` 第十一节已有一条，本章要给写法层面的处置，不重复结论）。
3. **设备与句柄占用**——`/dev/gpiochipN`、`/dev/gpiomem` 被另一进程占着时的表现、如何发现（只读命令复核）、以及多 agent 并行下同一块 GPIO 被两方写的风险与排查顺序。**这一条属本章核心**，因为本仓正在多窗口并行。
4. **去抖与边沿检测**——按钮抖动造成的重复触发、边沿回调丢事件、轮询与中断两种取法的误差量级（写清是手册口径还是推测）。
5. **`libgpiod` 1.x 与 2.x 的 API 差异在错误处理上的体现**——函数名/参数类型变了之外，返回值与 `errno` 语义是否也变，不确定就标存疑，别照抄教程。
6. **长驻程序的失效模式**——反复 `claim`/`free`、fd 泄漏、`sleep` 精度随负载漂移、日志写满 SD 卡。
7. **复核手段**——`gpiodetect` / `gpioinfo` / `gpioget` / `pinctrl` 的只读用法，怎么用它确认「程序以为的状态」与「内核实际状态」是否一致。
