# docs 索引与写作约定

> 这一层是全仓文档的**唯一约定源**：结构分层、按任务的入口、证据分档、敏感内容规则、写作规范。
> 各篇正文不再重复定义这些内容，只在篇首指向本篇，并保留「只有这一篇才需要的差异说明」。

## 一、目录结构与三层含义

```
docs/
├── README.md              ← 本篇：索引层（约定 + 跳转）
└── pi/
    ├── hardware/          ← 板子本身：规格、供电、状态读数
    │   ├── rpi-3b-hardware.md
    │   └── rpi-status.md
    ├── gpio/              ← 引脚与外设控制：接法、写法、复核
    │   ├── rpi-gpio-pinout.md
    │   └── rpi-gpio-robust.md
    └── access/            ← 接入：怎么连上它、连上之后怎么操作
        ├── rpi-network.md
        └── rpi-ssh.md
```

分类按**读它的人要做什么**，不按文档层次：硬件与状态同在 `hardware/` 是因为两者主语都是「这块板本身」；`rpi-ssh.md`（电脑侧）与 `rpi-network.md`（Pi 侧）同在 `access/` 是因为它们回答的是同一次「连上去」的两端。层次（主干 / 专章）由下面这张表表达，不由目录深度表达：

| 层 | 作用 | 篇 |
| --- | --- | --- |
| **索引层** | 分层、路由、全仓约定（本篇） | `docs/README.md` |
| **主干层** | 一类主题唯一一篇，承载规格、事实与实测 | [`rpi-3b-hardware.md`](./pi/hardware/rpi-3b-hardware.md)（硬件与选型）、[`rpi-gpio-pinout.md`](./pi/gpio/rpi-gpio-pinout.md)（GPIO 引脚与控制路径）、[`rpi-network.md`](./pi/access/rpi-network.md)（Pi 侧配置）、[`rpi-ssh.md`](./pi/access/rpi-ssh.md)（电脑侧操作） |
| **专章层** | 只回答一类问题，不重复主干内容 | [`rpi-gpio-robust.md`](./pi/gpio/rpi-gpio-robust.md)（GPIO 什么时候「看起来对、实际错」）、[`rpi-status.md`](./pi/hardware/rpi-status.md)（板子现在怎么样：读数、判读、假读数） |

**移目录为什么不断引用**：跨篇引用九成写成「`rpi-xxx.md` 第 N 节」的散文形式，只认文件名不认路径，而文件名在三个子目录之间**互不重复**，所以散文引用一条都没断；真正要改的只有带路径的 markdown 链接（`](./x.md)` / `](../README.md)`），它们已由 `scripts/check-agents.sh` 逐条验证目标存在。**新增一篇的落点规则**：先定分类目录，`docs/pi/` 根下直接放 `.md` 属违规（机检）；文件名要在全仓唯一，否则散文引用会歧义。

**一条主题只有一篇主干拥有它。** 发现同一事实在两篇里各写一份，删掉后写的那份、改成指向。已按此归并删除的历史源稿：`rpi-headless-access.md`、`rpi-display-headless.md`、`rpi-gpio-control.md`，以及 `rpi-3b-hardware.md` 自带的引脚表。

## 三、按任务入口（先定位到哪一篇）

| --- | --- |

## 四、证据分档（全仓唯一定义）

| 档 | 含义 | 标注要求 |
| --- | --- | --- |
| `[事实]` | 硬件规格，或本机已验证 | 可直接写 |
| `[本机实测]` | 在这台电脑上实跑得到，**与 Pi 无关** | 命令 + 实际输出 |
| `[待对端实测]` | 需要 Pi 在场才能判定，目前只是推断 | 写明缺的是哪台设备的哪个属性 |
| `[对端实测]` | 从电脑侧观察到板子的现象 | 日期 + 用的哪个客户端 |
| `[板上实测]` | 在板子上实跑得到（含 agent 经 SSH 执行） | 日期 + 命令 + 实际输出 |
| `[待验证]` | 依通用行为或既有文档推断，尚未跑过 | 保留，不得静默升格 |
| `[分歧未裁决]` | 本仓多篇互相矛盾且无权威依据 | 只并列双方立场，不择一 |

升格规则，四条：

1. 一条结论的档位**不得高于其推导链里最弱的一环**。
2. 只有「从电脑侧看到板子的现象」不能升 `[板上实测]`，它是 `[对端实测]`；端别记错会把结论归因给错误的机器。
3. 查官方文档裁决两篇冲突属**手册层结论**，不是实测；正文要写清这条裁的是文档口径，板上的仍挂 `[待验证]`。
4. 自建测试服务端（如本机 WSL 里的 sshd）跑出的结果属 `[本机实测]`，它证明的是「Linux + OpenSSH 语义」，替不了那台设备的属性。

## 五、敏感内容规则（2026-10-19 起）

口令、私钥、`authorized_keys` 公钥正文、账户名、主机名、SSID、局域网 IP **一律不写进仓库**，继续用 `<用户>` / `<主机名>` / `<SSID>` / `<addr>` 占位。主机键是指纹类公开材料，可以在 `rpi-ssh.md` 第四节作为比对基准落一次。

## 六、写作与结构规范（`scripts/check-agents.sh` 机检）

适用范围：`docs/pi/<分类>/` 下的主干与专章。本篇自身是索引层，只受第 1、7 条约束。

1. 文档只放 `docs/pi/<分类>/`——`hardware` / `gpio` / `access` 三个目录，**`docs/pi/` 根下直接放 `.md` 属违规**，`docs/` 下除本篇与 `pi/` 之外不放东西；分类目录不得为空。仓库根只留 `README.md`、`AGENTS.md`、`CLAUDE.md`、`QODER.md`。**文件名在全仓唯一**（散文引用只认文件名，重名即歧义）。
2. 每篇恰好一个 H1；H1 之后紧跟 blockquote，首行 `> 用途：`、次行 `> 边界：`（写明本篇**不**回答什么、归哪一篇）。
3. blockquote 之后是 `## 本篇结构`，逐条列出该篇全部 `##` 章（不含本节自身），一条一行。
4. `##` 是章、`###` 是节内小节，不跳级。章号沿用各篇已有形式（`1.` / `一、` / 无编号），**不重排**——跨篇引用大量写「第 N 节」「§4.1」这类承重指针，重排会全部指错。
5. 尾块按序出现，且落在本篇末尾：`## 相关文档`（本仓其它篇）→ `## 参考`（外部出处，可缺）→ `## 未覆盖事项`（可缺）→ `## 变更记录`（必须有，固定最末）。四个尾块都不编号。
6. `## 变更记录` 按轮次追加、只加不减、新条目在上；单次任务的过程细节不进文档，进 `.ai/`。
7. 指向本仓其它篇写成**相对链接**（相对该文件自己所在目录），机检目标存在；提到**已删除的历史源稿**时不写成链接，用行内代码并注明「已并入某篇」，否则断链检查看到的会是历史陈述而不是活引用。形如：

   ```md
   <!-- 在 docs/pi/gpio/rpi-gpio-pinout.md 里 —— -->
   [`rpi-gpio-robust.md`](./rpi-gpio-robust.md) —— 同目录的专章
   [`rpi-ssh.md`](../access/rpi-ssh.md) —— 跨分类，上跳一级再进
   [`docs/README.md`](../../README.md) —— 索引层（各篇都在 docs/pi/<分类>/ 下，故两级）
   ```

   历史源稿写成 `rpi-headless-access.md`（行内代码，不带链接）。
